# خطة النسخة 2 — تطبيق ويندوز + مستودع ملفات + أتمتة المونتاج بـ opencode

> الحالة: خطة معتمدة للانتظار. عند إعطاء أمر «ابدأ» تُنفَّذ المراحل بالتوازي عبر subagents.
> المشروع الحالي يبقى نفسه (لا مشروع جديد)؛ نضيف طبقة Electron وطبقة أوامر جديدة فوق الكود القائم.

## 1. الخلاصة

- لا حاجة لمشروع جديد. البرنامج الحالي (HTML/CSS/JS بلا إطار + `localStorage` + خادم ستاتيكي) يُغلَّف داخل Electron،
  ويُضاف له جسر IPC للوصول إلى نظام الملفات وتشغيل `opencode` على الجهاز.
- كل الإضافات تُبنى كوحدات جديدة: `electron/` للعملية الرئيسية، و`js/repo.js`، `js/opencode.js`، `js/automation-ui.js` للواجهة.
- التغييرات في الملفات القائمة تبقى محدودة (توجيه، أزرار، تبويب، حقول بيانات جديدة + ترقية مخطط البيانات إلى v2).

## 2. قرارات افتراضية (قابلة للتغيير بكلمة واحدة)

## 3. بنية المستودع على القرص

```text
<المستودع>/                                  ← مجلد يختاره المستخدم
├─ mosque-media-office.repo.json             ← ملف التعريف والفهرس (v1)
├─ mosque-media-office.data.json             ← مرآة بيانات البرنامج (احتياط تلقائي)
├─ إعلانات رمضان/                            ← مجلد مجموعة
│  └─ 20260810 - إعلان افتتاح المسجد/
│     ├─ output/                             ← كل ما يخرجه الذكاء الاصطناعي (نهائي)
│     └─ opencode/                           ← كل ما هو تقني/مسودات
│        ├─ config.json                      ← إعداد opencode لهذه المهمة (صلاحيات محدودة)
│        ├─ AGENTS.md                        ← عقد العمل مع الوكيل
│        ├─ status.json                      ← حالة المهمة وتقدّمها (يكتبه الوكيل)
│        ├─ run.json                         ← سجل التشغيل من البرنامج (الحقيقة النهائية)
│        └─ logs/run-<jobId>.jsonl           ← بث أحداث opencode كاملًا
└─ بدون مجموعة/
```

```json
{
  "kind": "mosque-media-office-repo",
  "schema": 1,
  "repoId": "rpo_8f3a…",
  "createdAt": "2026-11-14T10:00:00.000Z",
  "updatedAt": "2026-11-14T10:05:00.000Z",
  "app": { "name": "mosque-media-office", "version": "2.0.0" },
  "machine": { "host": "PC-HADI", "platform": "win32" },
  "groups": {
    "grp_101": { "name": "إعلانات رمضان", "folder": "إعلانات رمضان" }
  },
  "tasks": {
    "tsk_205": {
      "title": "إعلان افتتاح المسجد",
      "groupId": "grp_101",
      "folder": "إعلانات رمضان\\20260810 - إعلان افتتاح المسجد",
      "createdDate": "2026-08-10",

```

- القراءة أولًا من الملف، ثم مطابقة المعرّفات مع البيانات المحلية.
- إن وُجد الملف: ربط تلقائي. إن وُجد مجلد باسم مجلد لكن بلا ملف: يُعرض «استيراد مستودع» يفحص البنية ويعيد بناء الفهرس.
- المسارات تُخزَّن نسبية للمستودع دائمًا (حتى ينتقل المستودع بين الأجهزة).

### 3.2 قواعد التسمية

- تنظيف المحارف الممنوعة في ويندوز: `\ / : * ? " < > |`، وحذف النقاط/المسافات في النهاية.
- الحروف العربية مسموحة كما هي؛ الطول الأقصى للاسم 60 حرفًا (حماية من حد 260 حرفًا للمسار).
- التكرار: `الاسم (2)`, `الاسم (3)`… مع تسجيل الاسم النهائي في الملف.
- عند تغيير اسم مجموعة/مهمة: إعادة تسمية المجلد فعليًا + تحديث الفهرس (خيار في الإعدادات، مفعّل افتراضيًا).
- الأرقام العربية تُوحَّد إلى لاتينية في بادئة التاريخ فقط.

## 4. عقد الأتمتة مع opencode

### 4.1 التشغيل

```text
cwd = <مجلد المهمة>
opencode run --format json --model <provider/model> --auto \
  --title "<عنوان المهمة>" --session <job.sessionID||جديد> \
  "<نص البرومت + الملاحظات + نص العقد>"
```

- اكتشاف الأمر: `opencode` من `PATH`، وإلا من مسارات شائعة (`%APPDATA%\npm\opencode.cmd`)، مع فحص يدوي في الإعدادات.
- فحص الصحة عبر `opencode --version` و`opencode models` (لائحة الموديلات + ذاكرة آخر اختيار).

### 4.2 العقد المُرسَل (يُكتب أيضًا في `opencode/AGENTS.md` و`opencode/config.json`)

1. المصادر في مجلد المهمة. اقرأها ولا تنقلها.
2. كل ناتج نهائي → `output/` فقط.
3. كل المسودات والسكربتات والسجلات التقنية → `opencode/` فقط.
4. لا تلمس مجلدات أخرى في المستودع.
5. حدّث `opencode/status.json` بعد كل خطوة رئيسية.
6. عند الانتهاء: ضع الناتج النهائي في `output/` وضع `status.json` بحالة `done`.
7. النص العربي للمخرجات النهائية، وأسماء ملفات واضحة.

### 4.3 ملف الحالة الذي يكتبه الوكيل

```json
{
  "state": "working",
  "phase": "قص المقاطع",
  "percent": 45,
  "etaSeconds": 300,
  "message": "أستخرج اللقطات المناسبة",
  "outputs": ["output/preview.mp4"],
  "updatedAt": "2026-11-14T10:07:00.000Z"
}
```

`state`: `working | done | failed | blocked` (كل ما عدا ذلك يُعامل كـ unknown).

### 4.4 الحالة التي يكتبها البرنامج

`opencode/run.json` = `{ jobId, taskId, model, startedAt, endedAt, exitCode, status, steps[], tokens, cost, error }`،
و`logs/run-<jobId>.jsonl` يحتفظ بكل الأحداث كما وردت.

### 4.5 شريط التقدّم

- المصدر الأول: `percent` من `status.json` (يُراقَب بـ `fs.watch` + استطلاع كل ثانية).
- الاحتياط: تقدّم غير محدّد + عدّاد خطوات من أحداث `step_start` / `tool_use` / `step_finish` لتيار JSONL.
- الوقت المتوقع للنهاية: `etaSeconds` من الوكيل، ويُعرض «متبقٍ ~5 دقائق»، وإن لم يتوفر: «جارٍ…».
- الإلغاء: إنهاء شجرة العملية على ويندوز (`taskkill /PID … /T /F`) + تحديث `run.json` بحالة `cancelled`.

## 5. جسر Electron (IPC)

`electron/main.js` يحمل: نافذة واحدة، بروتوكول `app://` ثابت الأصل (حتى لا تضيع بيانات `localStorage` بسبب تغيّر المنفذ)،
قائمة عربية، منع التنقل الخارجي، وتسجيل معالجات الوحدات.

`electron/preload.js` يعرض `window.MMO` فقط (بلا Node في الواجهة):

```js
window.MMO = {
  isDesktop: true,
  repo: { pick, get, link, unlink, detect, ensureFolders, openFolder, syncManifest, revealPath, readManifest },
  store: { readMirror, writeMirror },
  opencode: { health, models, start, cancel, listJobs, subscribe, readStatus },
  system: { platform, openExternal, appInfo }
}
```

كل دوال `repo` تتحقق أن المسار داخل المستودع (منع `..`)، وكل الدوال تُرجع `{ ok, data }` أو `{ ok:false, message }`.

## 6. تغييرات البيانات والواجهة

### 6.1 البيانات (الترقية إلى v2)

- `VERSION = 2`, `STORAGE_KEY` يبقى، و`normalize()` يقبل v1 ويرقّي تلقائيًا.
- `settings.repo = { path, repoId, linkedAt, autoRename, lastSyncAt } | null`
- `settings.ai = { lastModel, opencodePath, modelFilter: { mode: 'all'|'allow', allowed: [], blocked: [], hidden: [] }, modelsCache: { at, list } }`
- `prompts[]`: `{ id, name, description, content, createdAt, updatedAt }` — تُدار كالقوالب تمامًا (إضافة/تعديل/حذف/تكرار).
- `automations[]`: `{ id, taskId, promptId, promptName, model, notes, promptText, status, progress, phase, etaSeconds, startedAt, endedAt, exitCode, error, sessionID, usage: { input, output, reasoning, cacheRead, cacheWrite, costUSD }, steps }`
- دوال جديدة في `Data`: `prompts()`, `createPrompt`, `updatePrompt`, `deletePrompt`, `duplicatePrompt`, `linkRepo`, `unlinkRepo`, `startAutomation`, `updateAutomation`, `activeAutomation(taskId)`, `automationStats(range)`, `automationDailySeries(from,to)`.
- المرآة: `Data.save()` يستدعي (بشكل غير معطّل) `MMO.store.writeMirror(snapshot)` مع تأجيل 2 ثانية؛ وعند الإقلاع إن كان `localStorage` فارغًا ومرآة موجودة تُقترح الاستعادة.

### 6.2 الواجهة

| المكان | الإضافة |
|---|---|
| الشريط الجانبي + الشريط السفلي | تبويب **«الأتمتة»** بأيقونة روبوت وشارة بعدد المهام الجارية |
| بطاقة المهمة | أيقونة مجلد (فتح مباشر) + أيقونة روبوت (بدء الأتمتة) + مؤشر حالة صغير أثناء التشغيل |
| سطر الجدول | نفس الأيقونتين (تحويل السطر من `<button>` إلى `<div role="button">` لتفادي أزرار متداخلة) |
| تفاصيل المهمة | زر «فتح المجلد» + زر «أتمتة بالذكاء الاصطناعي» أعلى النافذة |
| المجموعات | أيقونة مجلد لكل مجموعة + «إنشاء المجلدات الناقصة» |
| الإعدادات | قسم **«المستودع»**: اختيار مجلد، حالة الربط، مسار، مزامنة الآن، إعادة إنشاء المجلدات، فك الربط — وقسم **«الأتمتة»**: فحص اتصال opencode، مسار الأمر، إعادة جلب الموديلات، **تقييد الموديلات** (قائمة كاملة بمفتاح مسموح/ممنوع حتى لا يُختار موديل غالٍ)، الموديل الافتراضي وآخر اختيار |
| الشاشة الرئيسية | بطاقة **استهلاك الأتمتة آخر 30 يومًا** بالدولار + عدد التشغيلات ونسبة النجاح — توضع **بجانب** بطاقة «مهام قيد المتابعة» في شبكة عمودين، لا تحتها |
| التقارير | قسم **إحصائيات الأتمتة**: التشغيلات والنجاح/الفشل، التكلفة بالدولار، التوكنات (إدخال/إخراج)، التكلفة حسب الموديل، والتكلفة حسب المجموعة/المهمة، ومخطط زمني للاستهلاك |
| تبويب الأتمتة | قائمة المهام الجارية (تقدّم/طور/وقت متبقٍ/إلغاء/فتح السجل)، سجل المنتهية، وإدارة البرومتات |
| نافذة تأكيد الأتمتة | اختيار البرومت، تحرير النص كاملًا، ملاحظات، اختيار الموديل (مع تذكّر آخر اختيار)، ملخص «سيُحفظ في…» |
| نافذة المهمة | شريط حالة الأتمتة الأخيرة (نجحت/فشلت/قيد التشغيل) + زر فتح `output` |

### 6.3 سلوك في وضع المتصفح

إن لم يوجد `window.MMO` (فتح `index.html` مباشرة): يظهر تنبيه «المجلدات والأتمتة تحتاج تطبيق سطح المكتب»، وتبقى بقية الوظائف تعمل.

### المرحلة 0 — الأساس (تبدأ فورًا، تسلسلية قصيرة، أنا أنفّذها)

### المرحلة 1 — أربعة مسارات متوازية (subagents)

| المسار | الملفات التي يملكها فقط | المهمة |
|---|---|---|
| **A — المستودع** | `electron/repo.js`, `js/repo.js` | اختيار/اكتشاف/ربط، قراءة وكتابة ملف التعريف، تسمية وتنظيف وتفريد، إنشاء مجلدات المجموعات والمهام، إعادة التسمية، الفهرسة، فتح المجلد، كشف المجلدات الناقصة، إعادة البناء |
| **B — محرك opencode** | `electron/opencode.js`, `js/opencode.js` | فحص الصحة والمسارات، لائحة الموديلات وذاكرتها، تشغيل/إلغاء العمليات، تحليل JSONL، مراقبة `status.json`، كتابة `run.json` و`AGENTS.md` و`config.json`، حدود التزامن، استئناف بعد إغلاق البرنامج |
| **C — تبويب الأتمتة والبرومتات** | `js/automation-ui.js`, `css/automation.css` | شاشة الأتمتة كاملة (جارية/سجل/تقدّم/إلغاء)، إدارة البرومتات، نافذة تأكيد الأتمتة (منفصلة عن الصفحة كما طُلب) |
| **D — الدمج في الشاشات** | `js/views.js`, `js/modals.js`, `js/icons.js`, `css/components.css` | أيقونات المجلد/الروبوت في البطاقة والسطر والتفاصيل، بادجات الحالة، أزرار المجموعات، إعادة هيكلة سطر المهمة |

## 8. المخاطر والمعالجة

| الخطر | المعالجة |

| تعديل الوكيل لملفات المصدر | تحذير في نافذة التأكيد + نسخ احتياطي اختياري للمصادر قبل التشغيل |
