# خطة v2.2.0 — إدارة المساحة والأرشفة بعيدة المدى

> النطاق: مؤشرات المساحة، الأرشفة إلى مستودع خارجي مع تحقق الهاش، سلة محذوفات أسبوعية، تبويب المستودع،
> إعادة ربط القرص عند تغيّر الحرف، تنظيم أيقونات، إعادة توزيع بطاقات الإعدادات، وتنظيف بطاقة المجموعة
> ونموذج إنشاء المهمة، مع ضمان أن المثبّت يحدّث النسخة القديمة دون فقد البيانات.

---

## 1. الشكل النهائي للتطبيق

### التنقل

- الشريط الجانبي: **نظرة عامة · المهام · المجموعات · القوالب · الأتمتة · الأعضاء · التقارير · المستودع · الإعدادات**.
- «المستودع» قسم مستقل تحت عنوان فرعي **التخزين** (بين التقارير والإعدادات).
- الجوال: يبقى الشريط السفلي كما هو (الرئيسية، المهام، المجموعات، التقارير، الأتمتة، المزيد)؛
  «المستودع» يُفتح من قائمة «المزيد» لتفادي ازدحام الشريط.

### الصفحة الرئيسية

- بطاقة إحصاء خامسة داخل `stats-grid`:
  `hard-drive` + **مساحة الوسائط** + الحجم المستخدم + شريط نسبة رقيق جدًا + «المتاح: …».
  عند عدم ربط مستودع: القيمة «—» ونص صغير «لم يُربط مستودع».
- أسفلها سطر واحد بلا عناصر لافتة: `المصادر 2.1 GB · المخرجات 8.4 GB · opencode 0.9 GB`.
- رابط نصي وحيد «إدارة المستودع» ينقل إلى التبويب.

### بطاقة المهمة

- يبقى ارتفاعها كما هو.
- في شريط التاريخ أسفل البطاقة يُضاف شريحة صغيرة هادئة:
  `hard-drive` + `1.2 GB` مع `title` تفصيلي («المصادر 0.4 · المخرجات 0.7 · opencode 0.1»).
- لا تُظهر شيئًا إذا لم يُربط مستودع أو لم يتم الفحص بعد.
- المهام المؤرشفة تحمل شارة `archive` صغيرة بجانب شريحة المجموعة.

### تفاصيل المهمة

- قسم جديد **المساحة** أسفل بيانات المهمة:
  - إجمالي + شريط مكوّن من ثلاثة أجزاء (مصادر/مخرجات/opencode).
  - ثلاثة صفوف: أيقونة القسم، الاسم، الحجم، نسبة من إجمالي المهمة.
  - **تحت كل صف زرّان صريحان**: `archive` «أرشفة» (نقل إلى المستودع الخارجي) و`trash` «حذف» (نقل إلى سلة المحذوفات).
  - إن كان القسم مؤرشفًا: شارة `archive` + اسم المستودع + زر «استعادة» بدل زر الأرشفة.
  - الإجراءان يستخدمان نفس محرك الأرشيف/السلة المتحقق، ويعرضان تأكيدًا يذكر الحجم والوجهة.
- تبقى نفس الإجراءات متاحة أيضًا من تبويب المستودع (الصفوف القابلة للتوسيع) لمن يريد إدارتها مجمّعة.

### بطاقة المجموعة (الشكل الجديد)

```
┌──────────────────────────────────────────────┐
│ ▣ المجموعات                    [▣] [archive] [⋯] │
│ اسم المجموعة                                  │
│ ▓▓▓▓▓▓░░░░  3/5 · 60%                         │
│ ⌗ 5 مهام   ◌ 2 مفتوحة   ⚠ 0 متأخرة   ▤ 1.2 GB  │
│ [avatars]                        [فتح المهام] │
└──────────────────────────────────────────────┘
```

- يُحذف نهائيًا: «لا يوجد وصف»، اسم القالب، مسار المجلد، «كل المراحل عامة».
- الوصف يظهر فقط إذا كان موجودًا (سطران كحد أقصى).
- الإحصاءات تصبح أيقونة + رقم + كلمة قصيرة فقط، والمتأخرة تلوّن بالأحمر عند وجودها.
- الإجراءات: فتح المجلد (قائمة مستودعات)، أرشفة المجموعة، قائمة تعديل/حذف.
- شريحة المساحة تفتح تبويب المستودع مفلترًا على المجموعة.

### نموذج إنشاء المهمة

- اختيار المجموعة يصبح **شبكة بطاقات مسطحة** (عمودان على الشاشات المتوسطة، عمود واحد على الجوال)
  داخل إطار خفيف:
  - نقطة لون المجموعة 8px (بلا هالة).
  - اسم المجموعة + «5 مهام» كنص ثانوي.
  - المحدد: حد 1px بلون المجموعة + دائرة `check` صغيرة، **بلا تدرّج ولا توهج ولا ظل ملوّن**.
- بقية النموذج كما هي: التاريخ أساسي، والإعدادات المتقدمة قابلة للطي.

### تبويب المستودع


- كل صف مهمة قابل للتوسيع إلى ثلاثة أقسام، ولكل قسم: فتح، أرشفة، حذف (إلى السلة).
- للمهمة المؤرشفة بالكامل: شارة «مؤرشفة» + زر «استعادة».
- المستودع غير المتصل يظهر باهتًا مع «غير متصل» وسببه (المسار غير موجود) وزر إعادة ربط.
- «آخر العمليات»: آخر 10 عمليات أرشفة/استعادة/حذف مع الحجم والنتيجة (شفافية ومراجعة).

### الإعدادات

- تبقى البطاقات كما هي وظيفيًا، لكن التوزيع يصبح **أعمدة متراصّة (masonry)** لا شبكة صفوف:
  - 3 أعمدة ≥1360px، عمودان 901–1359، عمود واحد ≤900.
  - لا بطاقة بعرض عمودين، ولا فراغات عشوائية بين الصفوف؛ أعلى البطاقات في كل عمود مصطف،
    والمسافات 13px أفقيًا وعموديًا، والحشو الداخلي موحّد 18px.
- بطاقة المستودع تعرض: المسار، الحالة، السعة، آخر مزامنة، أزرار أيقونية.
- بطاقة البيانات المحلية تصبح «بيانات التطبيق» لتمييزها عن مساحة الوسائط.
- مزامنة توزيع البطاقات بعد الرسم وعند تغيير الحجم (debounce 120ms) دون فقد حالة النماذج.

## 2. مبادئ غير قابلة للتفاوض

1. **لا حذف قبل التحقق**: لا يُحذف أي ملف مصدر قبل أن يُكتب في الوجهة ويُعاد حساب SHA-256 له ويطابق الأصل.
2. **المصدر لا يُمَس عند الفشل**: أي خطأ أو إلغاء يترك المصدر كما هو، وينظّف الملفات المؤقتة فقط.
3. **لا كتابة خارج جذر المستودع**: كل مسار يُمرّر عبر `resolveInside` نفسه الموجود في `repo.js`.
4. **الحذف يمرّ عبر `.trash`** عندما يكون المستودع مربوطًا؛ الحذف النهائي إجراء صريح منفصل.
5. **لا أرشفة أثناء تشغيل أتمتة** على نفس المهمة، ولا حذف قسم يعمل عليه وكيل.
6. **البيانات لا تُفقد عند الترقية**: نفس `appId` و`productName`، ونسخة احتياطية قبل أي ترحيل.

## 3. نموذج البيانات — الإصدار 3

الترحيل من v2 يحافظ على كل الحقول الحالية ويضيف فقط:

```js
settings.repo = {                     // كما هو + label/volume/capacity
  path, repoId, autoRename, linkedAt, lastSyncAt,
  label: 'المستودع الأساسي',
  volume: { label, serial, fs, total, free, at },
  lastScanAt
}

settings.archives = [{                 // مستودعات طويلة الأمد
  id: 'arc_xxxxxxxx',                  // معرّف محلي ثابت
  repoId: 'rpo_...',                   // من mosque-media-office.repo.json
  path: 'E:\\MosqueArchive',
  label: 'هارد الأرشيف',
  volume: { label, serial, fs, total, free, at },
  linkedAt, lastSeenAt, lastScanAt,
  status: 'online' | 'offline'
}]

settings.storage = {                  // آخر لقطة فحص (تظهر فورًا عند الإقلاع)
  scannedAt,
  totals: { used, free, capacity },
  sections: { sources, output, opencode, trash, other },
  repos: { [repoId|'primary']: { used, free, capacity, sections, online } }
}

task.archived = {                     // أقسام انتقلت فعليًا إلى مستودع خارجي
  output: {
    repoId: 'rpo_...',                // معرّف المستودع الوجهة
    archiveId: 'arc_xxxxxxxx',        // معرّف السجل المحلي
    rel: 'الريلز/20260810 - …/output',// المسار النسبي وقت الأرشفة
    at, bytes, files,
    receipt: '.mmo-archive/index/task_x.json'
  },
  sources: { … }, opencode: { … }
}

task.storage = { sources, output, opencode, total, at }   // لقطة صغيرة للبطاقة
```

- `task.folder` يبقى مسار المهمة في المستودع الأساسي (توافق كامل مع المحرك الحالي).
- عند أرشفة قسم كامل نحذف مجلده من الأساسي فقط بعد التحقق، وقد يبقى مجلد المهمة فارغًا أو يحتوي أقسامًا أخرى.
- `group.storage` لا يُخزّن؛ يُحسب من المهام عند العرض.
- `.trash` و`.mmo-archive` و`.incoming` مستثناة من كل حسابات المساحة.

### الترحيل

- `Data.VERSION = 3`.
- `normalize()` يقبل v2 بلا فقد: يضيف `archives: []`, `storage: null`, `archived: {}` لكل مهمة.
- قبل الكتابة الأولى بعد الترقية: نسخة JSON كاملة في
  `%APPDATA%\mosque-media-office\backups\pre-v3-<timestamp>.json` عبر IPC جديد `store:backup`.
- اختبار ترحيل بلقطة v2 حقيقية (من `test/fixtures` أو لقطة مُولّدة) والتأكد من تطابق كل الحقول القديمة.

## 4. طبقة Electron الجديدة

### 4.1 `electron/storage.js`

مسؤول عن الفحص والسعة وإعادة الربط:

- `scan({ repos, tasks, force })`
  - يمشي على كل مستودع مرة واحدة بـ `fs.promises.opendir` (تخطي `.trash`, `.mmo-archive`, `.incoming`).
  - يجمّع الأحجام حسب بادئة مجلد المهمة إلى: `sources` (ملفات جذر المهمة)، `output`، `opencode`
    (شامل `logs`)، وأي ملفات فضفاضة في مجلد المجموعة تُحسب `other`.
  - يقرأ السعة بـ `fs.statfs` (total/free/used).
  - كاش 60 ثانية لكل مستودع + إمكانية `force`.
  - يبث `mmo:storage:progress` كل 250ms: `{ repoId, phase, scannedFiles, bytes }`.
- `locate({ items })`
  - كل عنصر `{ id, role, label, path, rel, sections }`؛ يتحقق من بقاء المسار داخل الجذر ويعيد
    `[{ ...item, absolute, exists }]`.
  - تُستخدم لقائمة «فتح المجلد» المنسدلة.
- `volume({ path })`
  - label + serial على ويندوز عبر `Get-CimInstance Win32_LogicalDisk` (child_process، لا صلاحيات مدير)،
    وfallback إلى `fs.statfs` على غير ويندوز.
- **إعادة الربط عند تغيّر الحرف (يدوية وآمنة):**
  - بطاقة المستودع غير المتصل تعرض «إعادة ربط»؛ يختار المستخدم المجلد الجديد.
  - يُقرأ `mosque-media-office.repo.json`: إن طابق `repoId` يُحدَّث المسار تلقائيًا،
    وإن اختلف يُطلب تأكيد صريح قبل الربط، ولا تُحذف ملفات.
  - لا يوجد فحص خلفي لأحرف الأقراص عند الإقلاع (تفاديًا لفحص أقراص ضخمة بلا طلب).

### 4.2 `electron/archive.js`

محرك النقل المتحقق (أرشفة/استعادة/سلة):

**خوارزمية نقل قسم واحد:**

1. التحقق من المسارين داخل جذري المستودعين + منع التداخل.
2. تعداد الملفات (المسار، الحجم، mtime) وحساب الحجم الكلي؛ التأكد من مساحة الوجهة
   (`free > bytes + max(200MB, 2%)`).
3. لكل ملف: نسخ إلى `dest/.incoming/<uuid>.part` مع حساب SHA-256 أثناء البث، ثم `fsync`،
   ثم إعادة قراءة الملف في الوجهة وحساب الهاش ومقارنته بالأصل.
4. عند تطابق الكل: إعادة تسمية ذرّية إلى المسار النهائي (مع الحفاظ على mtime).
5. كتابة إيصال `.mmo-archive/index/<taskId>.json` يتضمن كل ملف وحجمه وهاشه + ملخص في `index.json`.
6. تحديث `status.json` للمستودع (إن وُجد) ثم **حذف المصدر** فقط الآن.
7. عند أي فشل/إلغاء: حذف `.incoming` فقط، وإرجاع رسالة عربية دقيقة، والمصدر سليم.

**إضافات:**

- إلغاء عبر `AbortController` لكل مهمة، وطابور واحد لكل مستودع وجهة (لا نقلان متوازيان لنفس القرص).
- تعارض وجهة موجودة: إن طابق الإيصال والهاش → تعامل كـ«مؤرشف سابقًا» (اختيار: إكمال الحذف أو إبقاء الاثنين)،
  وإلا رفض مع رسالة واضحة.
- استعادة = نفس الخوارزمية بالاتجاه المعاكس، مع رفض الكتابة فوق مجلد موجود.
- إصلاح عند الإقلاع: إن وُجد إيصال مكتمل والمصدر ما زال موجودًا → اقتراح «إكمال الأرشفة» أو «تراجع».

**السلة `.trash`:**

```
<trash-root>/.trash/20261116-143012-a1b2/
  entry.json
  payload/<الشجرة الأصلية>
```

`entry.json`:

```json
{
  "schema": 1,
  "id": "trs_...",
  "repoId": "rpo_...",
  "kind": "task | group | section",
  "taskId": "task_x", "groupId": "grp_x", "section": "output",
  "originalRel": "الريلز/20260810 - …/output",
  "createdAt": "...", "expiresAt": "...",
  "bytes": 812345, "files": 12,
  "record": { "…snapshot of task/group data…": true }
}
```

- النقل للسلة داخل نفس القرص = `rename` ذرّي؛ عبر أقراص = نسخ متحقق ثم حذف.
- الاستعادة تعيد الشجرة إلى `originalRel`، وإن كان `record` موجودًا تُستعاد المهمة/المجموعة أيضًا.
- الحذف النهائي: تأكيد صريح + إزالة المجلد والإيصال.
- الانتهاء: 7 أيام ثابتة؛ تُفرَّغ العناصر المنتهية تلقائيًا عند فتح تبويب المستودع (وقبل عرض السلة).
  لا حذف صامت أثناء العمل إن كانت السلة تحوي عناصر ستنتهي اليوم — يظهر تنبيه في التبويب.

### 4.3 عقود IPC الجديدة

كلها بالشكل `{ ok, data }` أو `{ ok:false, message, code }` وتضاف إلى `docs/ipc-contract.md`.

```ts
storage:scan({ repos, tasks, groups, force? })
  -> { scannedAt, totals, sections, repos: { [id]: { used, free, capacity, sections, online } },
       tasks: { [taskId]: { sources, output, opencode, total, files, exists } } }

storage:locate({ items:[{ id, role, label, path, rel, sections }] })
  -> { locations: [{ ...item, absolute, exists }] }

storage:volume({ path }) -> { label, serial, fs, total, free }

repo:register({ path, role:'archive', label? }) -> { path, manifest, created }

archive:start({ type:'archive'|'restore', taskId, section, from, to, rel, sectionRel })
  -> { jobId }
archive:cancel({ jobId }) -> { cancelled: true }
archive:restore(payload) -> { jobId }          // نفس start مع type=restore
archive:reconcile({ repoPath }) -> { pending: [...] }
archive:purgeExpired({ repoPath }) -> { removed, bytes }
archive:progress  (event) { jobId, phase, file, filesDone, filesTotal, bytesDone, bytesTotal }
archive:done      (event) { jobId, ok, data:{ bytes, files, receipt }, error?, code? }

trash:move({ repoPath, rel, section, whole, meta }) -> { entry }
trash:list({ repoPath }) -> { entries: [...] }
trash:restore({ repoPath, entryId }) -> { restoredTo, entry }
trash:delete({ repoPath, entryId }) -> { removed, id }
trash:purge({ repoPath }) -> { removed, bytes }

store:backup({ snapshot, label? }) -> { path }
```

### 4.4 الأمان

- كل عمليات `archive:*` و`trash:*` تمرّ بنفس بوابة `guard` في `main.js`.
- إن كانت الإعدادات مقفلة بكلمة مرور: الأرشفة مسموحة (لا تفقد بيانات)، والحذف/الإفراغ يتطلبان فتح القفل.
- سجل عمليات `settings.storageLog` (آخر 50): النوع، المهمة، الحجم، النتيجة، الوقت.

## 5. واجهة المستودع — تفاصيل التنفيذ

- ملفات جديدة: `js/repo-view.js`, `css/repo.css`، وتسجيل المسار في `Views.render` و`pageMeta` و`app.js`.
- المصدر الوحيد للحقيقة عند العرض: `Data.get().settings.storage` (لقطة) + `settings.repo/archives`؛
  الفحص الطازج يطلب عند فتح التبويب وعند الضغط على «تحديث».
- شريط السعة: `used / capacity` مع `aria-valuenow`، وتفصيل الأقسام بألوان هادئة من متغيّرات المشروع.
- جدول «أكبر المهام»: ترتيب افتراضي تنازلي بالإجمالي، وأعمدة قابلة للترتيب (المصادر/المخرجات/opencode/الإجمالي).
- صف قابل للتوسيع (`<details>` أو زر `chevron-down`) بثلاثة صفوف أقسام.
- المستودع الخارجي غير المتصل: بطاقة باهتة + «إعادة ربط» + شرح أن الملفات لم تُفقد.
- زر «ربط مستودع خارجي»:
  1. اختيار مجلد.
  2. `repo:detect` → إن وُجد تعريف: اعرض «مستودع موجود» واسمه وسعته.
     إن لم يوجد: أنشئ تعريفًا بدور `archive` و`repoId` جديد (بتأكيد المستخدم).
  3. حفظ السجل في `settings.archives` + فحص أولي + toast.
- عند فتح تبويب المستودع يُستدعى `storage:scan` مرة واحدة (مع كاش) ويُحدّث `Data` ثم الواجهة.

### قائمة «فتح المجلد» المنسدلة

- `Views.folderButton` يتوسّع ليعرض:
  - زر أيقونة `folder-open`.
  - إن كان للمهمة/المجموعة موقع واحد فقط → يفتح مباشرة (كما الآن).
  - إن كان أكثر من موقع → قائمة `menu-pop` بنفس نمط قوائم التطبيق:
    ```
    المستودع الأساسي     C:\…\rel      متصل
    هارد الأرشيف E:      E:\…\rel      متصل · مخرجات
    ```
    كل صف يفتح `repo:open({ repoPath, relPath })` للموقع المحدد.
  - المواقع المفقودة تظهر معطّلة مع سبب «المسار غير موجود».
- لا حاجة لفتح القائمة عند عدم ربط مستودع.

## 6. الأيقونات — لفة كاملة

### أيقونات جديدة

| الأيقونة | الاستخدام |
|---|---|
| `hard-drive` | مستودع/قرص (أساسي أو خارجي) ومساحة الوسائط |
| `folder-source` | مجلد المصادر (سهم إلى الداخل) |
| `folder-output` | مجلد المخرجات (سهم إلى الخارج) |
| `unlink` | فك ربط مستودع |
| `copy-plus` | تكرار مهمة/برومت |
| `rotate-ccw` | إعادة تشغيل تشغيل منتهٍ |
| `trash-restore` | استعادة من سلة المحذوفات |

### إصلاح التشابه والتعارض

| المشكلة الحالية | الحل |
|---|---|
| `folder` (مخرجات) و`folder-open` (مجلد المهمة) متشابهان | `folder-open` = فتح فقط، و`folder-source`/`folder-output` داخل تفاصيل المساحة |
| النقطة الخضراء الدائمة على زر المجلد (`.task-folder-btn.has-folder::after`) | تُحذف القاعدة نهائيًا؛ يُكتفى بلون الأيقونة + `title` يوضح «المجلد موجود/غير موجود» |
| `archive` مستخدمة لبطاقة النسخ الاحتياطي | النسخ الاحتياطي `download`، و`archive` للأرشفة فقط |
| `external` و`external-link` | يبقى `external-link` للروابط، ويُستبدل `external` بـ`info` لتفاصيل التشغيل |
| `trash` للحذف وفك الربط وإزالة الشعار/كلمة المرور | `unlink` لفك ربط المستودع؛ `trash` للحذف فقط |
| `database` لبيانات التطبيق ومساحة المستودع | `database` للبيانات المحلية فقط، `hard-drive` للوسائط |
| `activity` لتفاصيل التشغيل والخطوات | `info` للتفاصيل، `activity` للإحصاء فقط |
| `power` لإعادة التشغيل | `rotate-ccw` |
| `copy` للتكرار والنسخ | `copy` للنسخ، `copy-plus` للتكرار |
| `grid` لزر «المزيد» | يبقى؛ لا تعارض وظيفي |

- **إزالة زر فتح مجلد الخرج نهائيًا** من: تفاصيل المهمة، صفوف التشغيل، نافذة تفاصيل التشغيل.
  يبقى الوصول إلى المخرجات عبر مجلد المهمة أو تبويب المستودع.
- جولة تحقق آلية: لا زر أيقوني بلا `title` + `aria-label`، ولا استخدامان مختلفان لنفس الأيقونة في سياقين متضادين.

## 7. المثبّت والترقية في المكان

### ما سيُضبط

- الإبقاء على: `appId: com.mosque.mediaoffice`، `productName`، `shortcutName`، `nsis` per-user.
- إضافة صريحة: `nsis.deleteAppDataOnUninstall: false`, `nsis.runAfterFinish: true`.
- عدم تغيير `productName` أو `appId` أو مجلد التثبيت الافتراضي — هذا ما يجعل NSIS يتعرّف على النسخة
  السابقة ويستبدلها في مكانها.
- مسار البيانات `%APPDATA%\mosque-media-office` مستقل عن إصدار التطبيق.
- الترقية من 2.1.0 إلى 2.2.0 تُشغّل ترحيل v2→v3 مع نسخة احتياطية مسبقة.

### التحقق العملي (ضمن الاختبارات)

1. تثبيت `2.1.0` صامتًا في مجلد اختبار `%LOCALAPPDATA%\Programs\MmoUpgradeTest`:
   `"…-2.1.0-x64.exe" /S /D=C:\…\MmoUpgradeTest`
2. تشغيل النسخة المثبتة بـ`MMO_USER_DATA` مؤقت، إنشاء مهمة/مجموعة/مستودع، إغلاقها.
3. تشغيل مثبّت `2.2.0` صامتًا بنفس `/D`.
4. التحقق من:
   - وجود تثبيت واحد فقط في «التطبيقات»، ونفس مجلد التثبيت.
   - `app.getVersion() === 2.2.0`.
   - بقاء المهمة والمجموعة والمستودع وكلمة المرور بعد الترقية.
   - عدم ظهور اختصار سطح مكتب مكرر.
   - وجود نسخة `backups/pre-v3-*.json`.
5. توثيق النتيجة في `README` و`docs/ipc-contract.md`، وإضافة فحص آلي
   `test/installer-upgrade.js` (يُشغّل عند توفر المثبّتات، وإلا يتخطى برسالة).

## 8. المخاطر والحلول

| الخطر | الحل |
|---|---|
| انقطاع الكهرباء/القرص أثناء النقل | الكتابة في `.incoming` + إيصال قبل حذف المصدر + مصالحة عند الإقلاع |
| تغيّر حرف القرص | فحص تلقائي لتعريف المستودع عند الإقلاع + إعادة ربط يدوية آمنة |
| نفاد مساحة الوجهة | فحص مسبق بهامش، ورفض واضح قبل نسخ أي بايت |
| فحص بطيء على هارد خارجي | كاش 60s، تقدم مرئي، فحص عند الطلب لا في كل رسم |
| تعارض مجلد موجود في الوجهة | مقارنة الإيصال والهاش؛ لا استبدال صامت |
| فقد البيانات عند الترقية | نفس هوية التطبيق + نسخة احتياطية قبل الترحيل + اختبار تثبيت حقيقي |
| أرشفة مهمة تعمل الآن | رفض مع رسالة «أوقف التشغيل أولًا» |
| بطاقات الإعدادات تتحرك بعد الرسم | توزيع الأعمدة قبل إظهار المحتوى (`visibility`) وdebounce عند تغيير الحجم |
